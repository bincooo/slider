# 拼图验证码缺口识别工具（Puzzle Captcha Gap Detector）

基于 **局部对比度分析（饱和度 + 亮度反差）** 的滑动拼图验证码缺口定位工具。

给定一张背景图（`bg.png`，图中存在一个抠图形成的缺口）和一张拼图碎片图（`block.png`，带透明通道，形状与缺口一致），程序会自动：

1. 提取拼图碎片的真实形状（去除透明边）；
2. 在背景图上滑动该形状，寻找"形状内部"与"形状外围"在**饱和度、亮度**上反差最大的位置；
3. 输出缺口的坐标，并生成一张用矩形框标注出缺口位置的背景图，便于人工核验。

---

## 原理说明

大多数滑动验证码在生成缺口时，会把对应区域"抠出" → 做模糊/变暗/降饱和处理 → 再拼回背景图。因此：

- 缺口区域内部的 **饱和度通常明显低于** 周围正常背景；
- 缺口区域内部与周围背景往往还存在一定的 **亮度差异**。

基于此，算法思路如下：

1. **提取拼图形状 mask**：读取碎片图的 alpha 通道，找到不透明区域的最小外接矩形并裁剪，得到形状 mask（`shapeMask`）。
2. **生成外围参照环**：对形状 mask 做膨胀（形态学 dilate），减去原始形状，得到紧贴形状外侧一圈的"环形参照区域"（`ringMask`），用于和形状内部做局部对比，而不是和整张图的全局统计做对比，抗干扰能力更强。
3. **提取背景图特征矩阵**：将背景图转换为 HSV 空间，提取每个像素的饱和度（S）和亮度（V），得到与背景图等大的两个浮点矩阵。
4. **滑动窗口匹配**：将形状 mask 在背景图上逐像素滑动，对每个候选位置分别统计：
    - 形状内部像素的平均饱和度 / 平均亮度；
    - 外围环像素的平均饱和度 / 平均亮度。
    
   计算综合得分：
    - satDiff = 外围平均饱和度 - 内部平均饱和度
    - brightDiff = 内部平均亮度 - 外围平均亮度
    - score = satDiff * 1.0 + brightDiff * 0.3
    得分最高的位置即判定为缺口所在位置。
5. **搜索范围优化**：利用拼图碎片在背景图中原本所处的行号（`baseY`）作为先验，只在其上下一定像素范围内（`yTolerance`）搜索，并跳过碎片自身所在的左侧区域（`skipLeft`），避免误匹配、减少计算量。

---

## 使用方法

1. 将背景图和拼图碎片图放入 gift/ 目录，并按需修改 main.go 中的文件路径：

```go
bgImg, err := loadImage("gift/bg2.png")
blockImg, err := loadImage("gift/block2.png")
```
2. 运行程序：
```go
go run main.go
```
3. 查看控制台输出，示例：
```
bg尺寸: (0,0)-(660,390)
block尺寸: (0,0)-(660,390)
拼图形状边界框: (30,120)-(90,180)
推测缺口Y坐标: 120
匹配结果 -> X: 452, Y: 118, 得分: 0.3127

======================
缺口X坐标: 452
======================
```
4. 打开 gift/marked.png，可以看到背景图中缺口位置被绿色矩形框标出，用于直观验证识别是否准确。

## 关键参数说明

|参数 | 位置 | 说明 |
| --- | --- | --- |
alphaThreshold | main() | 判定像素是否"不透明"的阈值（0-65535），用于提取拼图形状边界和 mask |
膨胀半径 4 | dilateMask(shapeMask, 4) | 外围参照环的宽度，越大参照区域越宽，可根据拼图碎片尺寸调整 |
yTolerance（示例中为 8） | matchByLocalContrast(...) 调用处 | 允许在推测的缺口行上下浮动搜索的像素范围，过小可能漏检，过大会增加耗时 |
skipLeft | main() | 跳过背景图最左侧一段区域，避免把拼图碎片当前所在原位置误判为缺口 |
得分权重 1.0 / 0.3 | matchByLocalContrast() | 饱和度反差与亮度反差在综合得分中的权重，可根据具体验证码样式调优 |
